# RawCull v1.8.1 Follow-up Review Notes

Date: 2026-05-15
Source reviewed: `analysever180.md`
Scope: findings from the v1.8.0 model-layer analysis that look valid enough to act on.

This document intentionally filters the longer analysis down to the findings I would prioritize. It excludes issues that looked speculative, overstated, or better handled as later style cleanup.

## Recommended Fixes

### ✅ 1. `ExecuteCopyFiles` security-scoped URL cleanup

File: `RawCull/Model/ParametersRsync/ExecuteCopyFiles.swift`

The report is correct that `URL.startAccessingSecurityScopedResource()` is not automatically paired when the `URL` value is released. `sourceAccessedURL` and `destAccessedURL` must always be stopped explicitly.

Current status:

- `cleanup()` now stops both security-scoped URLs and clears the stored references.
- Normal rsync termination calls `cleanup()` after the completion handler has consumed the result.
- `executeProcess()` failure, source/destination acquisition failure, explicit close, sheet disappearance, and `deinit` now all route through the same cleanup path.

Implemented change:

- `cleanup()` is explicitly idempotent and safe to call from completion, failure, cancellation, dismissal, and `deinit`.
- The `executeProcess()` catch path calls `cleanup()` directly because `ExecuteCopyFiles` is already `@MainActor`.
- `ExecuteCopyFiles.close()` cancels any active rsync process and then calls `cleanup()`.
- `CopyFilesView` calls `close()` from the close button and sheet disappearance path before dropping `executionManager`.
- `deinit` is `isolated` and uses the same idempotent cleanup as a last-resort fallback.

Completion criteria:

- Every started source/destination security scope is paired with exactly one stop call.
- Cleanup runs on rsync success, rsync launch failure, user close/cancel, sheet dismissal, and object deallocation fallback.
- Progress continuations are finished once, and `streamingHandlers` / `activeStreamingProcess` are cleared once.

Priority: high.

### ✅ 2. `ExecuteCopyFiles` rsync progress callback actor isolation

File: `RawCull/Model/ParametersRsync/ExecuteCopyFiles.swift`

`ExecuteCopyFiles` is `@MainActor`, but the rsync streaming `fileHandler` callback may be invoked from a background pipe/process callback. The closure currently reads `self?.progressContinuation` directly.

Current risk:

- MainActor-isolated state is accessed from a callback that is not declared `@MainActor`.
- This can become a strict-concurrency diagnostic and is conceptually racy even if `AsyncStream.Continuation` itself is thread-safe.

Recommended change:

Use one of these approaches:

- Hop to the main actor:

```swift
fileHandler: { [weak self] count in
    Task { @MainActor in
        self?.progressContinuation?.yield(count)
    }
}
```

- Or redesign progress streaming so the continuation is captured as a local Sendable value and does not require reading MainActor state from the callback.

Priority: high.

### ✅ 3. `ZoomPreviewHandler` decodes sidecar JPGs on the MainActor

File: `RawCull/Model/Handlers/ZoomPreviewHandler.swift`

The sidecar JPG fast path calls `loadCGImage(from:)` synchronously before returning a task. Because the namespace enum is implicitly MainActor-isolated under the project default isolation setting, this can block the UI while ImageIO opens and decodes a large Sony JPEG.

Current risk:

- Opening the zoom overlay for an existing sidecar JPG can pin the main thread.
- The fast path returns `Task {}` after doing the expensive work, so the returned task is not meaningfully cancellable.

Recommended change:

- Move the sidecar decode into a `Task.detached(priority: .userInitiated)`.
- Apply the image back on `MainActor`.
- Ensure cancellation is checked before mutating the view model.

Priority: high.

### ✅ 4. `RawCullViewModel` security-scoped catalog lifecycle is too broad

Files:

- `RawCull/Model/ViewModels/RawCullViewModel.swift`
- `RawCull/Views/RawCullSidebarMainView/extension+RawCullView.swift`

The picker starts security-scoped access and the view model tracks the URL, but resources are currently stopped only in `RawCullViewModel.deinit`.

Current risk:

- A long app session that opens many catalogs can accumulate security-scoped accesses.
- Cleanup at app teardown is too late to represent the catalog lifecycle.
- The comment says access is stopped “when the source is removed or the app terminates,” but the source-removal cleanup path is not present in the reviewed code.

Recommended change:

- Add explicit MainActor lifecycle methods such as `stopSecurityScopedAccess(for:)` and `stopAllSecurityScopedAccess()`.
- Call them when a source/catalog is removed, closed, or replaced.
- Leave `deinit` either empty or as a final fallback after normal lifecycle cleanup exists.

Priority: high.

### 5. Catalog cancellation uses fire-and-forget actor calls

File: `RawCull/Model/ViewModels/RawCullViewModel+Catalog.swift`

`cancelCatalogLoad()` cancels tasks and then calls actor cancellation methods through unstructured `Task { await actor.cancel...() }` blocks.

Current risk:

- The actor reference is cleared before cancellation has completed.
- A new catalog load can start while previous actor cleanup is still running.
- Cancellation order is hard to reason about.

Recommended change:

- Prefer an async cancellation path that awaits actor cancellation.
- If a synchronous entry point must remain, route cancellation through a stored serial task so repeated cancels run in order.

Priority: medium/high.

### ✅ 6. `RawCullViewModel+Thumbnails` method/property name collision

File: `RawCull/Model/ViewModels/RawCullViewModel+Thumbnails.swift`

The view model has both:

```swift
var memorypressurewarning: Bool
func memorypressurewarning(_ warning: Bool)
```

Swift accepts this, but it is hard to read and easy to break during future renames.

Recommended change:

- Rename the method to `setMemoryPressureWarning(_:)`.
- Consider renaming the property to `memoryPressureWarning` in the same pass if the UI references are manageable.

Priority: medium.

### 7. `CullingModel.upsertRecord` ignores `dateTagged` for existing records

File: `RawCull/Model/ViewModels/CullingModel.swift`

When a file record already exists, `dateTagged` is ignored even when the caller passes a fresh date from `updateRatings` or `applyRatings`.

Current behavior:

- First rating date is preserved.
- Later rating changes do not update the tag date.

This may be intentional if `dateTagged` means “first tagged.” If it means “last rating change,” this is a correctness bug.

Recommended change:

- Decide and document the semantics.
- If it means latest edit, update `dateTagged` when a rating update is applied.

Priority: medium.

### 8. Saved culling JSON lives in `~/Documents`

Files:

- `RawCull/Model/JSON/WriteSavedFilesJSON.swift`
- `RawCull/Model/JSON/ReadSavedFilesJSON.swift`

The saved culling state is written to the user Documents directory. App state is usually better placed in Application Support.

Current risk:

- The file may sync through iCloud Documents.
- Repeated debounced writes can create unnecessary sync and backup churn.
- The file is app-private state, not user-authored document content.

Recommended change:

- Move `savedfiles.json` to `~/Library/Application Support/RawCull/`.
- Add one-time migration from the old Documents location.
- Until migration exists, consider excluding the file from backup/iCloud metadata if practical.

Priority: medium.

### 9. Similarity indexing discards completed work on cancellation

File: `RawCull/Model/ViewModels/SimilarityScoringModel.swift`

`indexFiles` accumulates embeddings in `localEmbeddings` and merges them only if the task is not cancelled.

Current risk:

- Cancelling a long indexing run loses all embeddings computed during that run.

Recommended change:

- Merge embeddings incrementally inside the result loop, or periodically flush partial results before checking cancellation.

Priority: medium.

### 10. Burst grouping repeatedly unarchives all embeddings

File: `RawCull/Model/ViewModels/SimilarityScoringModel.swift`

`groupBursts(files:)` unarchives every stored Vision feature print for each grouping run. The cancellation/generation logic helps during slider drags, but a settled threshold change still pays the full unarchive cost.

Recommended change:

- Cache unarchived observations for the current `embeddings` snapshot.
- Invalidate the cache when embeddings change.

Priority: medium.

### 11. Focus calibration lacks cooperative cancellation checks

File: `RawCull/Model/ViewModels/FocusMaskModel.swift`

The v1.8.0 analysis notes that parallel burst calibration does not appear to check cancellation often enough. I did not re-audit the whole focus engine in this pass, but the recommendation is sound for long-running image scoring work.

Recommended change:

- Add `Task.isCancelled` or `try Task.checkCancellation()` checks between batches and inside per-file loops.
- Return partial/no result cleanly when cancelled.

Priority: medium.

### ✅12. `CreateStreamingHandlers` passes an environment dictionary with an empty key

File: `RawCull/Model/Handlers/CreateStreamingHandlers.swift`

The streaming handler currently passes:

```swift
environment: ["": ""]
```

That is suspicious for a process environment. It may be ignored by the rsync wrapper, but it is better to pass `nil` or an empty dictionary if the API allows it.

Recommended change:

- Verify `RsyncProcessStreaming.ProcessHandlers` expectations.
- Use `[:]` or `nil` instead of an empty-string key.

Priority: low/medium.

### 13. `FocusPoint` accepts zero sensor dimensions

File: `RawCull/Model/ViewModels/FocusPointsModel.swift`

`FocusPoint.normalizedX` and `normalizedY` divide by `sensorWidth` and `sensorHeight`. The parser only checks that four numeric values exist.

Recommended change:

- Reject focus points where sensor width or height is less than or equal to zero.
- Optionally clamp normalized coordinates if malformed metadata can produce out-of-range positions.

Priority: low/medium.

## Findings I Would Not Prioritize From `analysever180.md`

### ✅ `SharpnessScoringModel.scoreFiles` re-entrance guard

The report says the guard is broken because there are awaits before `_scoringTask` is assigned. In the reviewed code, there is no `await` between checking `_scoringTask` and assigning it. Because `scoreFiles` is MainActor-isolated, another MainActor invocation should not interleave in that specific window.

I would still consider moving `_scoringTask = workTask` closer to task creation for clarity, but I would not treat this as a high-priority correctness bug.

### Iterator capture in scoring/indexing loops

The iterator pattern in `SharpnessScoringModel.scoreFiles` and `SimilarityScoringModel.indexFiles` is harder to read than an index cursor, but the iterator is mutated by the parent task/group loop, not by the child tasks. I would classify this as cleanup, not a race.

### `RawCullViewModel` property count as a performance bug

Splitting the view model into smaller state objects may improve maintainability, but Swift Observation tracks property reads more precisely than older object-wide invalidation models. I would not treat the property count alone as a proven performance issue without measuring view invalidation.

### `RatingFilter.stars(Int)` unbounded associated value

This is a type-design improvement, but it is only a practical bug if invalid values can be created through UI, persistence, or tests. Lower priority than the resource and main-thread issues above.

### `FocusMaskEngine.computeSharpnessScalar` memory allocation warning

The report itself notes that the full-preview mask path may not hit the specific `render(toBitmap:)` allocation path. Keep an eye on memory, but verify with Instruments or targeted code reading before changing the focus pipeline.

## Suggested Fix Order

1. Fix `ExecuteCopyFiles` security-scoped cleanup and catch-path cleanup.
2. Fix `ExecuteCopyFiles` progress callback actor isolation.
3. Move `ZoomPreviewHandler` sidecar JPG decode off the MainActor.
4. Add explicit catalog/source security-scope cleanup in `RawCullViewModel`.
5. Make catalog cancellation await actor cleanup.
6. Rename `memorypressurewarning(_:)`.
7. Decide `dateTagged` semantics and adjust `CullingModel` if needed.
8. Plan `savedfiles.json` migration to Application Support.
9. Improve cancellation/partial-result behavior in similarity and focus scoring.
10. Address smaller cleanup items opportunistically.
